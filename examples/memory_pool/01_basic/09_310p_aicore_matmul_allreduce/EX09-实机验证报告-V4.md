## 1. 验证对象与口径

双 M 组（本次新增 M 参数化，`-DEX_MVAL` 编译开关）：

| 组 | A_half(每 rank) | B_half | C=recv | 全量矩阵语义 | 池 | 每 rank 计算量 |
|----|------|------|------|------|----|------|
| M=2048（默认） | [2048,2048] 8MB | [2048,2048] 8MB | [2048,2048] 8MB | A[2048,4096]×B[4096,2048] | 64MB | 8.6 GFLOP |
| M=4096（新增） | [4096,2048] 16MB | [2048,2048] 8MB | [4096,2048] 16MB | A[4096,4096]×B[4096,2048] | 64MB | 17.2 GFLOP |

- 三模式（同 kernel）：**fused（V4 口径）**= 算完一块即通知搬运一块，计算不等任何到达通知
  直接进入下一拍（生产环零同步点）；全部生产结束后统一 poll+累加 ｜ serial = 算完全部→
  统一 notify→逐 chunk 收+累加（零重叠基线）｜ pure = 仅 matmul

  = M/行数，超邮箱 64 槽自动跳档（M=4096 的 128KB 档为 128 chunk，SKIP），每配置 3 次取平均
- 数值校验：双端同种子 U[-1,1]，CPU FP64 参考，atol=0.1+rtol=0.01，每档三模式首轮全量校验

## 3. 性能结果（单位 ms；每格 `r0 / r1`）

### 3.0 指标定义（加速比 / 掩盖度 / 掩盖收益）

三模式耗时记号：Tfused / Tserial / Tpure（各模式整轮墙钟，3 次取平均）。

**加速比 = Tserial / Tfused**——相对零重叠基线的提速倍数；依赖 serial 基线自身的形态。

**掩盖度 = Tpure / Tfused**——fused 墙钟中"纯计算"所占份额：

- 分解：Tfused = Tpure + T暴露（T暴露 = 未被计算盖住的通信成本），故掩盖度 = 1 − T暴露/Tfused；
  越接近 1 = 通信在墙钟中越不可见
- **理论上限 < 1.00**：单 block 纪律下累加（N×τ_acc）与末笔传输必然暴露——M=2048 1024KB 档
  结构上限 ≈ 7.40/(7.40+0.45) ≈ 0.94，实测 0.92 已贴近天花板
- 失真边界：分母被与掩盖无关的固定成本撑爆时该指标失真（V2 时代 100ms 尾睡使其低至
  0.07），故须与 Tfused−Tpure 绝对差值联看

**掩盖收益 = T_hide / T_base（T_base = Tserial）**——相对无重叠基线，理论上可从墙钟中抹掉
的通信份额（wave 模型，参数映射与推导见 §3.4）：

- T_hide = min(T_matmul, T_AllReduce) × (W−1)/W；其中 T_matmul = Tpure，
  T_AllReduce = Tserial − Tpure，W = chunk 数（Tile=chunk、P=1 的映射依据见 §3.4）
- 物理含义：首 chunk 为流水填充（其传输暴露），其余 W−1 拍的计算窗口可覆盖的传输份额
- **实测对应值 = (Tserial − Tfused) / Tserial**（实现到的部分）；模型与实测之差 = 结构性暴露
  （累加 τ_acc、每拍 notify 固定开销），对账见 §3.4
- 与掩盖度分工：掩盖度度量"离通信免费的理想界还有多远"（份额口径，0.91-0.98）；
  掩盖收益度量"相对 serial 省掉了多少通信时间"（节省比例口径，0.03-0.11）——前者恒大于
  后者（Tserial > Tpure），两者联看才能区分"融合做得好"还是"serial 基线做得差"

### 3.4 掩盖收益（wave 模型，Overlap 空间 = T_hide/T_base）

**模型参数映射**（通用 wave 公式 → 本 kernel 实现）：

| 模型量 | 本 kernel 取值 | 依据 |
|--------|--------------|------|
| Tile 大小 T_m×T_n | chunkRows×N（整 chunk） | 通信粒度 = chunk：整块算完并 clean 后才能 notify 搬运 |
| Tile 数量 | ceil(M/chunkRows)×ceil(N/N) = chunk 数 N | 沿 M 均分 |
| AICore 数量 P | **1**（单 block 纪律） | 全部 Tile 由一个 AICore 串行处理 |
| wave 数 W | ceil(Tile 数量/P) = N | — |
| T_matmul | Tpure（实测） | 纯计算基线 |
| T_AllReduce | Tserial − Tpure（实测净通信，含传输+派单+累加） | serial 与 pure 之差 |
| T_base | Tserial（实测） | 无重叠基线墙钟 |

**可重叠比例 = (W−1)/W**：首 chunk 算完前通信无法启动（流水填充暴露），其余 W−1 拍的
计算窗口用于覆盖传输——恰为 V4 生产环结构的解析表达（传输(c) 与 matmul(c+1) 重叠）。

**推导表（r0）**：

| 组/档 | W | (W−1)/W | T_AR(ms) | T_hide = T_AR×(W−1)/W | 掩盖收益 = T_hide/Tserial |
|-------|---|---------|----------|----------|----------|
| M=2048 1024KB×8 | 8 | 0.875 | 0.92 | 0.81 | 0.10 |
| M=2048 512KB×16 | 16 | 0.938 | 0.97 | 0.91 | 0.08 |
| M=2048 256KB×32 | 32 | 0.969 | 1.11 | 1.08 | 0.08 |
| M=2048 128KB×64 | 64 | 0.984 | 1.31 | 1.29 | 0.05 |
| M=4096 1024KB×16 | 16 | 0.938 | 1.81 | 1.70 | 0.10 |
| M=4096 512KB×32 | 32 | 0.969 | 1.73 | 1.68 | 0.08 |
| M=4096 256KB×64 | 64 | 0.984 | 1.70 | 1.67 | 0.06 |

**模型 vs 实测对账**（以 M=2048 1024KB 为例）：模型 T_hide 0.81ms 中含结构性暴露的累加
（τ_acc≈0.45ms，单 block 下不可隐藏），扣除后 ≈0.36ms，与实测隐藏量（Tserial−Tfused
=0.32ms）吻合 ✓；细粒度档（128KB，64 拍）实测再低 ~0.3ms，对应每拍 notify 固定开销
（ENTIRE clean + 邮箱写 ≈5µs/拍 × 64 拍）。

**解读**：① 掩盖收益随 chunk 细化**下降**（0.10→0.05）——(W−1)/W 虽趋近 1，但 T_AR 内
每 chunk 固定编排开销线性增长、且 T_base 同时被每拍 notify 固定开销抬高，与"最佳划分
=1024KB"互为印证；② 当前 P=1 是单 block 纪律下的取值，若落地多 block（P=8，Tile 回到
cube 粒度 baseM×baseN），W 缩小、通信可按 wave 粒度流水，Overlap 空间将重新放大——
属 AICore 侧架构项，与 doorbell 攒批（压缩 T_AR 本身）正交。

## 4. 设计变更说明（V3 → V4 fused）

| | V3（消费先行，被本报告取代） | V4（单向同步生产环） |
|----|----|----|
| 稳态拍 | poll(c−1)→accumulate(c−1)→matmul(c)→notify(c) | matmul(c)→notify(c)（**零同步点**） |
| 归约位置 | 内联每拍 | 全部生产结束后统一进行 |
| 关键路径 | 每拍暴露 δ≈0.11-0.17ms（编排+传输固定时延，两 rank 锁步下无计算可藏） | 计算环无等待；末笔传输延迟被前 N−1 个累加吸收 |
| 对 δ 的鲁棒性 | 依赖 δ < τ_mm | 无条件（δ 任意大只延长尾部归约，不侵蚀计算窗口） |
| 总时间 | N×(τ_mm+τ_acc) + N×δ | N×(τ_mm+τ_acc) + 残余≈0 |

设计要点：① 归约挪尾的代价 = N×τ_acc 暴露——单 block 纪律下累加本就无法与计算重叠
（V3 中它也只是内联，并非真重叠），故挪尾无净损失；② C 区保持 SDMA 只读源不变，
终态仍落 recv 原地（V2 报告 §5#3 的双区设计不变）；③ 传输与计算的重叠转为结构性——
描述符随算随到，编排器在 CP1 并发派单（每 chunk 处理 0.1-0.17ms << 拍长）。

## 5. 结论

1. **融合净收益首次为正且全档成立**：双 M 组 7 个有效档加速比全部 ≥1.00（1.00-1.04x），
   掩盖度 0.91-0.98。fused−serial 的差值 = 真实被掩盖的传输+派单时间，随传输量线性放大
   （M=4096 差值 ~2 倍于 M=2048），因果闭环。
2. **V3 报告 §4.4 的两条预测双双命中**：C1 预测 Tfused ≈ 8.0-8.1ms（实测 8.00/8.11）；
   C2"增大 K 不可反超"在 V3 形态下成立——而 V4 通过消除每拍暴露（而非增大计算）使
   反超成立，验证了"时延型 vs 带宽型"的归因框架。
3. **剩余优化空间**：fused−pure 残差 ≈ N×τ_acc（0.45-0.9ms）+ 末笔传输残余，前者受单 block
   纪律约束（多 block/cube-vector 并行才是下一步，属 AICore 侧架构项）；后者可由 doorbell
   攒批压缩（编排器策略，serial 同步受益——注意攒批会使 fused/serial 差值收窄，对比实验
   时应固定一侧口径）。
4. **最佳划分结论变化**：V2/V3 时代"顶格 1024KB 最优"源于粗粒度摊薄固定延迟；V4 中
   各档加速比趋同（1.00-1.04x），chunk 粒度不再是敏感参数——传输已不再是瓶颈。
